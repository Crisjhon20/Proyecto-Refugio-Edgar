# Constitucion del Backend

## 1. Objetivo

Construir una API REST para administrar:

- Autenticacion del administrador.
- Registro y actualizacion de animales.
- Listado general de animales.
- Listado filtrado de animales.

El backend utilizara PostgreSQL y estara organizado en una arquitectura de tres capas.

## 2. Tecnologias

- Lenguaje: TypeScript.
- Runtime: Node.js.
- Framework HTTP: Hono.js.
- Base de datos: PostgreSQL.
- Cliente PostgreSQL: `pg`.
- Autenticacion: JWT.
- Manejo de JWT: `jose`.
- Encriptacion de contrasenas: `bcrypt`.
- Rondas de bcrypt: 8.
- Validacion: `Zod`.
- Configuracion: variables de entorno mediante `.env`.

## 3. Arquitectura

Se utilizara una arquitectura de tres capas:

```text
HTTP / Presentacion
        |
        v
Servicios / Logica de negocio
        |
        v
Persistencia / Base de datos
```

### Capa HTTP

Responsabilidades:

- Definir rutas.
- Recibir solicitudes.
- Validar parametros y cuerpos.
- Ejecutar controladores.
- Devolver respuestas HTTP.

Componentes:

- `routes/`
- `controllers/`
- `middlewares/`
- `schemas/`

### Capa de servicios

Responsabilidades:

- Aplicar reglas de negocio.
- Iniciar sesion.
- Generar JWT.
- Registrar y actualizar animales.
- Aplicar filtros.
- Coordinar repositorios.

Componente:

- `services/`

### Capa de persistencia

Responsabilidades:

- Abrir conexiones con PostgreSQL.
- Ejecutar consultas parametrizadas.
- Buscar administradores.
- Crear, actualizar y listar animales.

Componente:

- `repositories/`

## 5. Entidades

### Administrador

| Campo | Tipo |
| --- | --- |
| Identificador | INTEGER |

| Contrasena | TEXT |

### Animal

| Campo | Tipo |
| --- | --- |
| Identificador | INTEGER |
| Nombre | TEXT |
| Raza | TEXT |
| Edad | INTEGER |
| Sexo | TEXT |
| FechaIngreso | DATE |
| TipoAnimal | TEXT |

## 6. Reglas de negocio

### Administrador

- El usuario debe tener maximo 15 caracteres.
- La contrasena debe tener maximo 60 caracteres.
- La contrasena debe almacenarse usando bcrypt.
- Se utilizaran 8 rondas de bcrypt.
- El inicio de sesion requiere usuario y contrasena validos.

### Animal

- `Sexo` solo puede ser `Hembra` o `Macho`.
- `TipoAnimal` solo puede ser `Perro` o `Gato`.
- `FechaIngreso` se genera automaticamente mediante `CURRENT_DATE`.
- Solo administradores autenticados pueden gestionar animales.
- No se eliminaran animales porque esa funcionalidad no fue solicitada.

## 7. Requerimientos funcionales

- RF-01: El administrador puede iniciar sesion.
- RF-02: El cliente puede cerrar sesion eliminando su JWT.
- RF-03: Un administrador autenticado puede registrar un animal.
- RF-04: Un administrador autenticado puede actualizar un animal.
- RF-05: Un administrador autenticado puede listar todos los animales.
- RF-06: Un administrador autenticado puede filtrar animales por nombre, raza, sexo y tipo.

## 8. Endpoints

### Inicio de sesion

`POST /auth/login`

Body:

```json
{
  "usuario": "feresdev",
  "contrasena": "feresdev123"
}
```

Respuesta exitosa:

```json
{
  "token": "jwt"
}
```

El JWT sera almacenado y administrado por el cliente.

### Cierre de sesion

`POST /auth/logout`

El backend respondera confirmando la operacion. El backend no revocara ni almacenara tokens. El cliente eliminara el JWT localmente y no se implementara una lista negra de tokens.

### Registrar animal

`POST /animals`

Requiere JWT.

Body:

```json
{
  "nombre": "Max",
  "raza": "Labrador",
  "edad": 3,
  "sexo": "Macho",
  "tipoAnimal": "Perro"
}
```

`FechaIngreso` sera asignada automaticamente por PostgreSQL.

### Actualizar animal

`PUT /animals/:id`

Requiere JWT. Permitira modificar `Nombre`, `Raza`, `Edad`, `Sexo` y `TipoAnimal`.

### Listar animales

`GET /animals`

Requiere JWT y devuelve todos los animales registrados.

### Listar animales filtrados

`GET /animals?nombre=Max&raza=Labrador&sexo=Macho&tipoAnimal=Perro`

Requiere JWT. Los filtros disponibles son `nombre`, `raza`, `sexo` y `tipoAnimal`; todos son opcionales y combinables.

## 9. Autenticacion

### Inicio de sesion

1. Recibir usuario y contrasena.
2. Validar los datos con Zod.
3. Buscar el administrador por usuario.
4. Comparar la contrasena usando bcrypt.
5. Generar un JWT.
6. Devolver el token al cliente.

### Rutas protegidas

1. Recibir `Authorization: Bearer <token>`.
2. Verificar la firma del JWT.
3. Permitir o rechazar la solicitud.

Variables de entorno:

```env
PORT=3000
DATABASE_URL=postgresql://usuario:contrasena@localhost:5432/refugiodb
JWT_SECRET=clave-secreta
JWT_EXPIRES_IN=1h
BCRYPT_ROUNDS=8
```

## 10. Validacion con Zod

Se crearan esquemas para:

- Inicio de sesion.
- Registro de animales.
- Actualizacion de animales.
- Parametros de filtros.
- Identificadores numericos.

Validaciones principales:

- Usuario obligatorio.
- Contrasena obligatoria.
- Nombre obligatorio.
- Edad numerica y no negativa.
- Sexo limitado a `Hembra` y `Macho`.
- TipoAnimal limitado a `Perro` y `Gato`.
- Longitud maxima del usuario: 15.
- Longitud maxima de la contrasena: 60.

## 11. Contrasena inicial

El administrador utilizado por el backend sera `feresdev` con la contrasena inicial `feresdev123`. La contrasena recibida por el usuario seguira siendo `feresdev123`, pero el valor almacenado en PostgreSQL debera ser el hash bcrypt correspondiente generado con 8 rondas.

El seed SQL actual utiliza otro administrador. Antes de integrar el backend se debera actualizar el seed o crear una migracion para que el usuario y el hash almacenado coincidan con esta especificacion.

## 12. Fases de implementacion

### Fase 1: Especificacion

- Crear `backend/spec-kit-backend`.
- Crear `1.Constitucion.md`.
- Documentar tecnologias, arquitectura, entidades, endpoints, fases y reglas.

### Fase 2: Inicializacion

- Crear el proyecto Node.js.
- Instalar TypeScript y Hono.js.
- Configurar `tsconfig.json`.
- Configurar scripts basicos de ejecucion.
- Configurar variables de entorno.

### Fase 3: Conexion con PostgreSQL

- Configurar el pool de conexiones usando `pg`.
- Leer `DATABASE_URL`.
- Verificar la conexion con `refugiodb`.
- Crear los repositorios de administrador y animal.
- Usar consultas parametrizadas.

### Fase 4: Validaciones

- Crear esquemas Zod.
- Validar cuerpos de solicitudes.
- Validar parametros de rutas.
- Validar filtros.
- Crear respuestas uniformes para errores de validacion.

### Fase 5: Seguridad

- Configurar bcrypt con 8 rondas.
- Generar el hash de la contrasena inicial.
- Crear la generacion de JWT.
- Crear la validacion de JWT.
- Crear el middleware de autenticacion.
- Configurar errores para tokens ausentes, invalidos o expirados.

### Fase 6: Autenticacion

- Implementar `POST /auth/login`.
- Buscar al administrador.
- Comparar la contrasena con bcrypt.
- Generar y devolver el JWT.
- Implementar `POST /auth/logout`.
- Mantener el cierre de sesion del lado del cliente.

### Fase 7: Animales

- Implementar `POST /animals`.
- Implementar `PUT /animals/:id`.
- Implementar `GET /animals`.
- Implementar filtros mediante parametros de consulta.
- Proteger todas las rutas con JWT.
- Manejar animales inexistentes.
- Respetar las restricciones de PostgreSQL.

### Fase 8: Integracion final

- Registrar las rutas en Hono.
- Registrar los middlewares.
- Configurar el punto de entrada de la aplicacion.
- Verificar el flujo de autenticacion y acceso a las rutas de animales.
- Verificar la generacion automatica de `FechaIngreso`.
